# 05 争议与局限

写论文时，「知道这套系统会在哪里出错」比「知道它多准」更能体现你读懂了它。

## 已公开的具体失误

| 时间/场景 | 现象 | 原因 |
|---|---|---|
| 2007 澳网、迪拜赛 | 多次争议判罚，Nadal 质疑「出界球被判进」3 mm | 弹跳点估计的边界情形，误差与判定阈值同量级 |
| 2009 印第安维尔斯（Murray vs Ljubičić） | 系统显示球压在线上，慢镜头明显出界 | **误把第二次弹跳当成第一次**（球在线上反弹后又被捕获） |
| 2009 澳网（Federer vs Berdych） | 挑战时系统不可用 | 球场上有明显阴影，球检测失败 |
| 2012 意甲 Milan vs Juventus | 进球被误判未进 | 官方解释为「没有任何一台相机没拍到」，而是转播视角误导了观众 |

## 结构性的局限

1. **遮挡与受限视角**：门线系统声称 7 台中 2 台可见即可定位，但板球/足球场景里球员密集时，多台相机同时被挡的概率并不为零；FIFA 测试手册专门设了「受限视角」测试，就是因为这是真实失效模式。
2. **阴影、光照、球衣颜色**：球检测依赖视觉特征，强阴影与逆光会导致漏检（2009 澳网案例）。商业系统靠多相机冗余 + 高帧率降低概率，不能消除。
3. **红土与草地的差异**：法网长期不用 Hawk-Eye 而用球印，因为红土上的痕记本身就是证据；2021 马德里公开赛引入的是 FoxTenn（40 台地面相机 + 激光同步，最高 3000 fps），不是 Hawk-Eye。说明不同场地需要不同的测量范式。
4. **预测外推的不可验证性**：板球 LBW 的「球会不会击中门柱」是外推结果，没有真值可比；ICC 因此在 2012 年请 Cambridge 的 Computer Vision Consulting 对 Hawk-Eye 与 Virtual Eye 做独立测试，重点就是「外推预测是否正确」与「可靠跟踪的比例」。ICC 当时的口径很有参考价值：*如果 60 次 LBW 申诉里只有 50 次能给出可靠跟踪，就不算可靠；97/100 才算可接受*——**可靠性（能给出结果的比例）与准确性（给出结果的误差）是两个指标**。
5. **转播图不等于测量结果**：Hawk-Eye 的 3D 动画为了可读性会做视觉简化（球的渲染形状、线的粗细、透视夸张）。官方明确说过「任何转播慢镜头都挑不出错」，但观众对「看起来差一点」的直觉经常与几何事实相反。
6. **成本与公平性**：GLT 不是强制的，只有少数顶级联赛装得起；这本身是「技术提升公平性」叙事里的一个反例，讨论部分可以用一句话带过。

## 对我们的警示

- 我们的两帧问题**没有任何冗余**：定位错了没有第二组相机来纠正，模型错了没有更多帧来约束。Hawk-Eye 用硬件消灭的误差项（标定、量化、同步、遮挡），在我们这里全部转化为「模型假设 + 不确定度」。
- 因此论文里最有说服力的写法不是「我们的落点很准」，而是：
  1. 在什么观测噪声下，落点不确定度小于门框尺寸的多少百分比；
  2. 哪些参数（自旋、阻力系数、采样时刻）主导不确定度；
  3. 在什么条件下方法会失效（例如观测噪声 > 2 cm、或自旋 > 4500 RPM）。
